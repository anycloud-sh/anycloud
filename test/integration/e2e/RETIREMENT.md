# Bash retirement table

**Final.** The migration is complete; this record is frozen history and is no
longer validated.

This is the operative record for retiring legacy Bash end-to-end members under
the green-streak rule of [RFC 0017](../../../rfcs/0017-constrained-vitest-e2e.md)
(amendment 2026-09-25).

**Rule.** A member's Bash source may be deleted once its constrained Vitest
candidate has passed on **N green executions** on `main`. The green
executions need not be consecutive (owner decision 2026-09-27):

- `local-or-no-provision` members: N = 5. An execution is a `main` or
  pull-request Integration run in which the member's Vitest cell actually ran.
- `real-cloud` members: N = 3. An execution is a scheduled or dispatched run
  of the member's E2E workflow (`e2e-job`, `e2e-vm`, or `e2e-serve`) for its
  provider in which its Vitest cell actually ran.
- `real-cloud-gpu` members: N = 2, because GPU quota is scarce and those runs
  are rare. An execution is a run of `e2e-gpu` for the member's provider in
  which its Vitest cell actually ran. The class covers exactly the members whose execution needs a GPU
  instance; `gcp-disk-tier` runs in `e2e-gpu` on CPU instances and stays
  `real-cloud`.

Cancelled and skipped runs are not executions. A run in which the spec never
ran — the harness or the local API failed to start, or every provisioning
attempt ended `capacity-exhausted`/`insufficient-capacity` — is not an
execution either: it neither counts nor resets, and Notes may record it. A
failure blocks, resetting the streak to 0, only when a product or contract
assertion fails. An environmental failure that hits the candidate and its Bash
member identically in the same run — a third-party API quota, a provider
outage — is also **not an execution** for either, provided no product path is
implicated and nothing leaked (owner decision 2026-09-27, after the
`aws-recursion` round-4 GitHub-quota 403). A harness observation timeout, an
incomplete native read, or a fixture-cleanup or provider-side failure whose
cleanup was confirmed neither counts nor resets; the row's Notes records the
run. A spec that passed with failed post-steps is a green execution. Each
retirement batch after the first is
preceded by a passing mutation sample of its members (RFC 0017 "Mutation
gate"). Streaks are counted from the first run after
the amendment merged; `0` below means not yet measured. Where several rows name
the same Bash source, every one of them must reach N before the source is
deleted, and they are marked `retired` together.

**Retirement PR.** Delete the `.test.sh`, its Bash matrix cell, and any helper
under `test/integration/helpers/` with no remaining consumer; make the Vitest
cell a required check; review the member's assertion map under
`test/integration/e2e/qualification/assertion-maps/` for coverage parity; set
the row to `retired` with the merge date and the map's requirement count. A
member that must keep its Bash is marked `retained` with the reason in Notes.

**Coverage parity is checked.** Every `candidateEvidence` string in the
member's assertion map (`assertion-maps/<candidate name>.json`) is parsed as
`<file or dir/>: <identifiers> …`: file tokens (`*.ts`, `*.mjs`, `*.sh`,
`*.json`, `*.yml`, or `dir/`) resolve repository-relative, then relative to
`test/integration/e2e/`, then as a unique basename under `test/`, `src/`,
`ci/`, or `.github/`; camelCase, `UPPER_SNAKE`, `Owner.member`, and
`file.ts::member` tokens of four or more characters must occur as a word in one
of those files. Retired rows record the map's requirement count;
the map may not later hold fewer requirements unless Notes names each removal
as `dropped <id>: <reason>`. The check does not notice an assertion that still
exists but became weaker; that stays with the reviewer.
